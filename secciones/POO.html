1. ¿Qué es la Programación Orientada a Objetos (POO)?

La POO es un paradigma de programación, es decir, un modelo o estilo de desarrollo de software. En lugar de estructurar el código como una serie de funciones y líneas consecutivas (programación procedimental), la POO propone organizar el código simulando el mundo real a través de "Objetos".

Cada objeto en nuestro programa agrupa sus propias características particulares (llamadas propiedades o atributos) y sus propias acciones que puede realizar (llamadas métodos).

2. Los Pilares Base: Clases y Objetos

Para entender la POO, debemos entender la diferencia entre un molde y el producto final:

  • Clase: Es la plantilla, el molde o plano arquitectónico abstractor. Define qué propiedades y métodos tendrá un objeto, pero no contiene datos reales individuales.
  • Objeto / Instancia: Es el elemento real y concreto creado a partir del molde (clase). Ocupa un lugar único en la memoria RAM y tiene sus propios valores.

Ejemplo en JavaScript:

// Definimos el molde (Clase)
class Estudiante {
    constructor(nombre, edad) {
        this.nombre = nombre; // Atributo
        this.edad = edad;     // Atributo
    }
    
    // Método (Acción)
    saludar() {
        return `Hola, soy ${this.nombre} y tengo ${this.edad} años.`;
    }
}

// Instanciación: Creamos los objetos reales en la RAM
let alumno1 = new Estudiante("Miguel", 20);
let alumno2 = new Estudiante("César", 22);

console.log(alumno1.saludar()); // Muestra los datos de alumno1

3. Primer Pilar: Abstracción

La Abstracción consiste en reducir un objeto complejo del mundo real a sus características esenciales para el sistema, ignorando los detalles que no son relevantes para nuestro software.

Analogía: Si diseñamos un sistema escolar, un "Estudiante" necesita atributos como nombre, notas y cédula. Detalles como su tipo de sangre, su estatura o su color favorito se omiten porque no aportan valor al problema de estudio.

Ejemplo en JavaScript:

class EstudianteAcademico {
    constructor(cedula, nombre, nota1, nota2) {
        this.cedula = cedula;   // Dato esencial
        this.nombre = nombre;   // Dato esencial
        this.nota1 = nota1;     // Dato esencial académico
        this.nota2 = nota2;     // Dato esencial académico
        // Omitimos: estatura, peso, color favorito, pasatiempos, etc. (Eso es abstraer)
    }

    // Método que procesa los datos abstractos recolectados
    calcularPromedio() {
        let promedio = (this.nota1 + this.nota2) / 2;
        return promedio;
    }

    obtenerEstado() {
        return this.calcularPromedio() >= 10 ? "Aprobado" : "Reprobado";
    }
}

// Instanciación aplicando la abstracción
let estudianteVirtual = new EstudianteAcademico("V-30123456", "César", 18, 16);
console.log(`Estado: ${estudianteVirtual.obtenerEstado()} con promedio de ${estudianteVirtual.calcularPromedio()}`);

4. Segundo Pilar: Encapsulamiento

El Encapsulamiento consiste en ocultar o proteger los datos internos de un objeto del mundo exterior, impidiendo que sean modificados de forma directa o malintencionada. Para interactuar con estas propiedades protegidas, se crean métodos de puente públicos (conocidos como Getters para leer y Setters para modificar).

En JavaScript moderno, las propiedades privadas se declaran usando el símbolo # antes de su nombre.

Ejemplo en JavaScript:

class CuentaBancaria {
    #saldo; // Atributo 100% privado

    constructor(montoInicial) {
        this.#saldo = montoInicial;
    }

    // Método público controlado para modificar el saldo de forma segura
    depositar(dinero) {
        if (dinero > 0) {
            this.#saldo += dinero;
        }
    }

    // Getter público para poder ver el saldo sin alterarlo
    get obtenerSaldo() {
        return this.#saldo;
    }
}

let miCuenta = new CuentaBancaria(500);
miCuenta.#saldo = 0; // ❌ Error: JavaScript bloquea el acceso directo externo
miCuenta.depositar(200); // ✅ Forma correcta y segura

5. Tercer Pilar: Herencia

La Herencia es el mecanismo que permite crear una clase nueva (Clase Hija) basándose en una clase existente (Clase Padre). La clase hija adopta automáticamente todos los atributos y métodos de la clase padre, permitiendo reutilizar código y extender su comportamiento sin volver a escribirlo todo desde cero.

En JavaScript se implementa utilizando la palabra reservada extends y el método super() para invocar al constructor del padre.

Ejemplo en JavaScript:

// Clase Padre General
class Persona {
    constructor(nombre) {
        this.nombre = nombre;
    }
}

// Clase Hija Específica que hereda de Persona
class Profesor extends Persona {
    constructor(nombre, materia) {
        super(nombre); // Llama al constructor de Persona
        this.materia = materia; // Atributo único de Profesor
    }
}

let prof = new Profesor("Carlos Alfonzo", "Programación");
console.log(prof.nombre); // ✅ Funciona: heredó la propiedad 'nombre'

6. Cuarto Pilar: Polimorfismo

El Polimorfismo (múltiples formas) significa que un mismo método o acción puede comportarse de manera diferente según el objeto que lo ejecute. Permite que clases hijas redefinan o sobrescriban un método heredado del padre para adaptarlo a su propia necesidad.

Ejemplo en JavaScript:

class Animal {
    hacerSonido() {
        return "Sonido genérico...";
    }
}

class Perro extends Animal {
    // Sobrescribimos el método para adaptarlo al Perro
    hacerSonido() {
        return "¡Guau! ¡Guau!";
    }
}

class Gato extends Animal {
    // Sobrescribimos el método para adaptarlo al Gato
    hacerSonido() {
        return "¡Miau!";
    }
}

let misAnimales = [new Perro(), new Gato()];
// El mismo método 'hacerSonido()' dará respuestas totalmente distintas
misAnimales.forEach(animal => console.log(animal.hacerSonido()));

7. Ventajas Fundamentales del Paradigma

🎯 Beneficios Técnicos de usar POO

  • Reutilización de código (DRY - Don't Repeat Yourself): Mediante el uso de clases y herencia, puedes escribir la lógica de un componente una sola vez y reutilizarla en múltiples partes del sistema sin duplicar líneas de código, reduciendo drásticamente el tamaño del software.
  • Mantenibilidad y depuración eficiente: Al estar el código modularizado en objetos independientes, si se detecta un error en un comportamiento específico, el desarrollador sabe exactamente qué clase debe corregir. Los cambios internos en un objeto no rompen de forma impredecible el resto del sistema.
  • Modularidad para el trabajo en equipo: Permite dividir aplicaciones robustas en módulos o clases autónomas. Esto facilita que diferentes desarrolladores trabajen en paralelo en distintos objetos sin generar conflictos en el código fuente.
  • Seguridad de datos mediante encapsulamiento: Protege la integridad de la información sensible restringiendo el acceso directo a las propiedades críticas de los objetos. Solo los métodos autorizados y controlados (getters y setters) pueden leer o modificar los datos internos, evitando manipulaciones externas corruptas o accidentales.
  • Escalabilidad orgánica: Añadir nuevas funcionalidades o características al sistema es sumamente sencillo. Puedes extender el comportamiento de las clases existentes creando subclases a través de la herencia, permitiendo que el software crezca sin necesidad de reescribir la arquitectura base.
